# Webflow Bridge 商业化路线

> 状态：草案（待 darren 评审）｜基线：v1.2.5（MIT，Python 3.11+，stdlib-only）
> 范围：ToC + ToB 双线。本文是执行依据，不是宣传材料。所有数字为决策输入，
> 所有能力必须可验收。

---

## 0. 结论先行

**核心判断：本地浏览器桥这一层已经被证明是免费商品，不能靠卖桥收费。**

| 同构能力 | 价格 | 来源类别 |
|---|---|---|
| Playwright MCP（官方） | $0 | 官方开源 |
| Chrome DevTools MCP（官方） | $0 | 官方开源 |
| Steel Browser | $0（可自托管） | 开源 + 托管加价 |
| Kimi WebBridge | $0 | 同构竞品 |

桥 = 免费。桥之上能收费的只有四样：**管控、支持、托管、行业结果**。

- **ToC 卖"省时间"**：不用写脚本就能把常见任务跑起来（编排、模板、重试、跨设备同步）。
- **ToB 卖"管得住"**：企业要的不是"能自动化"，是"谁在什么时候对哪个站点做了什么、
  能不能拦、出了事能不能查、能不能吊销"。这正是桥厂商免费给不了的部分。
- 两条路**共享同一块地基**（安装、运行时、更新、结构化日志、许可、审计事件流）。
  **先做地基**：地基不做，ToC 装不上、ToB 审不了。地基本身不卖钱，但它决定两条线
  能不能开工。

### 阶段总览

| 阶段 | 周期 | 一句话目标 | 侧 | 收入 |
|---|---|---|---|---|
| Phase 0 共享地基 | 4–6 周 | 让陌生人能装上、用上、查得到 | 共享 | $0（不卖） |
| Phase 1 ToC Pro | 4–6 周 | 不写脚本也能跑常见任务 | ToC | $8–15/月 |
| Phase 2 ToB 企业版 | 8–12 周 | 企业敢在受管环境里放行 | ToB | $10/用户/月起 |

## 1. 三条铁律

> 这三条是架构红线，任何阶段不得违反。违反其一，对应商业线直接不存在。

### 铁律 1：审计事件流第一天就写

**为什么**：企业版卖的全部价值就是"谁 / 何时 / 对哪个站点 / 做了什么动作 / 结果"这条
链。审计不是功能，是数据结构。事后往**动作层**补审计 = 重构整条执行路径（每个 action
的 dispatch、每个 CDP 透传、每个错误分支都要回填）。第一天写，成本是一次性钩子；
第二年补，成本是整个 daemon 重写。哪怕初期只落本地文件、无人查看，也必须先落。

### 铁律 2：MIT 核心 + 专有组件（open core）

**为什么**：核心开源是获客与信任的来源（"数据不出本机"需要能被人审计），但企业功能
和 Pro 功能**必须**放专有侧。否则一开源，商业版就不存在——竞品可以原样 fork 后收钱。
边界划分原则见第 3 节。

### 铁律 3：永不加入遥测

**为什么**："零上传、数据不出本机"是卖点，不是限制；它是本地桥相对云浏览器唯一站得住
的差异点。一旦加入遥测，这条护城河当场消失，且与企业合规叙事自相矛盾。任何需要统计
的地方走**本地、匿名、可关闭、且默认关闭**。

## 3. 开放核心边界：MIT 侧 vs 专有侧

### 划分原则

1. **单人本地能用 → MIT 侧。** 桥本身、动作集、协议、单机审计落盘，一律 MIT。
2. **需要服务端 / 多用户 / 策略裁决 / 密钥签发 → 专有侧。** 这些是收费点，不放 MIT。
3. **审计的"写入"在 MIT，审计的"汇聚、导出、检索、防篡改校验服务"在专有侧。**
   数据格式公开（可被第三方审计），但企业级能力是专有。
4. 判断口诀：**能否用一个本地进程 + 一个本地文件表达？** 能 → MIT；需要协调多方
   （用户身份、集中策略、SIEM）→ 专有。

| 组件 | 侧 | 许可 |
|---|---|---|
| daemon 桥 / 动作集 / WS-HTTP 协议 | 共享 | MIT |
| 审计事件写入（本地 JSONL + hash 链） | 共享 | MIT |
| 审计 schema 定义与校验器 | 共享 | MIT |
| 一键安装包 / 自动更新 | 共享 | MIT |
| License key **校验**逻辑（离线可校验） | 共享 | MIT |
| License key **签发**与后台 | ToB/ToC | 专有 |
| 可视化编排 / 模板库 | ToC | 专有 |
| 跨设备配置同步（E2EE） | ToC | 专有 |
| 策略引擎 / 集中管理端 | ToB | 专有 |
| 审计导出（syslog/webhook）/ SIEM 对接 | ToB | 专有 |
| SSO / 多用户 / 设备注册吊销 | ToB | 专有 |
| 私有部署包 / 离线许可 | ToB | 专有 |

## 4. 四个阶段

### Phase 0 · 共享地基（4–6 周）

**目标**：让一个陌生人能装上、用上、查得到；为 ToC/ToB 两条线预置钩子。

**依赖**：无（起点）。
**风险**：安装包签名与公证（Windows EV 证书 + macOS notarization）是**长周期外部依赖**，
需第一周就启动申请；否则卡在最后一公里。内置运行时会使包体积升至 30–60MB，接受。

| # | 交付物 | 侧 | 许可 | 验收标准 |
|---|---|---|---|---|
| 0.1 | 一键安装包（Windows MSI/EXE + macOS pkg/dmg） | 共享 | MIT | 干净机器上双击安装，全程无需命令行；安装后 daemon 能被 launchd/服务拉起，popup 显示 Active；卸载后无残留进程与文件 |
| 0.2 | 内置 Python 运行时 | 共享 | MIT | 在**未装 Python** 的干净 Windows/macOS 上安装后直接可用；`python3 --version` 与本产品无关联；包体 ≤60MB |
| 0.3 | 自动更新（daemon + 扩展各自独立） | 共享 | MIT | daemon：启动时检查新版本，可自动升级并重启，升级失败自动回滚到上一版本；扩展：走商店/AMO 更新或签名清单自更新；**版本兼容保护**：daemon 与扩展协议版本不匹配时明确报错并拒绝执行，不静默降级 |
| 0.4 | 结构化日志（JSONL，替代 stdout 文本与 err 文件） | 共享 | MIT | 每条日志为一行合法 JSON，含 ts/level/event/字段；文件按大小轮转（默认单文件 ≤10MB、保留 5 份）；给定一次失败动作，能在日志里定位到对应结构化记录；不再新增无轮转的 `.err`（当前已 129KB 的那份迁移后停写） |
| 0.5 | 许可体系骨架（生成/校验/试用） | 共享（校验）/ 专有（签发） | MIT / 专有 | 离线可校验：断网输入合法 key 通过、非法/过期 key 拒绝并给出明确原因；试用期（如 14 天）到期后降级到免费档；**商店不支持付费扩展**，付费走自建通道，key 校验不依赖扩展商店 |
| 0.6 | 审计事件流 v0（架构钩子） | 共享 | MIT | 见第 5 节验收标准；本轮只需落本地 JSONL + hash 链，无需 UI |

**Phase 0 完成判据**：0.1–0.6 全部通过各自验收标准。任一不过，不进入 Phase 1。

### Phase 1 · ToC Pro（4–6 周）

**目标**：把"省时间"卖出去——不写脚本的用户也能把常见任务跑起来。

**依赖**：Phase 0 全部（尤其 0.3 更新、0.5 许可、0.6 审计）。
**风险**：模板库的**维护成本**会持续消耗人力（每个站点改版就要修模板）。对策：模板
只覆盖 5–10 个高频任务，其余交给编排让用户自建，不承诺全站支持。

| # | 交付物 | 侧 | 许可 | 验收标准 |
|---|---|---|---|---|
| 1.1 | 可视化编排（录制回放 / 任务列表 / 定时） | ToC | 专有 | 录制一次 3 步操作可回放成功；任务可保存、可命名；定时任务到点自动执行，执行记录能在本地看到成功/失败 |
| 1.2 | 模板库（发布 / 采集 / 填表等常见任务） | ToC | 专有 | 内置 ≥5 个模板；每个模板在干净账号上跑通一次，失败时给出可操作的错误提示；模板可被用户复制后修改 |
| 1.3 | 失败重试与断线续跑 | ToC | 专有 | 注入一次网络中断，任务自动重试并在恢复后续跑到完成；重试次数与间隔可配；续跑不重复已完成步骤 |
| 1.4 | 跨设备配置同步（端到端加密） | ToC | 专有 | 设备 A 保存的配置在设备 B 登录同一许可后可取回；同步内容在服务端不可读（E2EE，服务端只见密文）；可一键关闭同步 |

**Phase 1 完成判据**：1.1–1.4 全过；且付费流程（购买 → 拿 key → 激活 Pro）端到端走通。

---

### Phase 2 · ToB 企业版（8–12 周）

**目标**：让企业敢在受管环境里放行——这是"管得住"的四件套：**可审计、可拦截、
可确认、可管理**。

**依赖**：Phase 0（审计、许可、安装）；Phase 1 非硬依赖，但共享前端。
**风险**：合规材料（渗透测试 / SOC2）周期以**月**计，且需第三方；若目标客户是强合规
行业，必须在 Phase 2 第一周就启动，不能等功能做完再补。

| # | 交付物 | 侧 | 许可 | 验收标准 |
|---|---|---|---|---|
| 2.1 | 审计导出（SIEM 对接：syslog / webhook） | ToB | 专有 | 开启后，每条审计事件同时投递到 syslog 与 webhook；投递失败本地缓存并重试，不丢事件；给定 3 个动作，SIEM 侧能检索到对应 3 条、字段齐全、hash 链可校验 |
| 2.2 | 策略引擎（域名白/黑名单、动作级策略、默认拒绝） | ToB | 专有 | 配置域名黑名单后，对该域名动作被拒并记 `policy_decision=deny`；动作级策略可禁用某类动作（如 upload）；开启"默认拒绝"后未在白名单的动作全部被拒 |
| 2.3 | 高危动作人工确认卡点 | ToB | 专有 | 提交表单 / 上传 / 发送 / 付款四类动作触发确认，未确认则阻塞且记 `policy_decision=confirm`；确认/拒绝结果入审计 |
| 2.4 | 多用户与身份（每用户权限与 profile、SSO OIDC/SAML、设备注册与吊销） | ToB | 专有 | 用户 A/B 各自独立 session 与 profile，互不可见；SSO（OIDC 与 SAML 各一）可登录；管理员吊销某设备后该设备立即失去执行能力 |
| 2.5 | 集中管理端（看审计 / 配策略） | ToB | 专有 | 管理员可跨设备查看审计、下发策略；策略变更在目标设备下一次动作前生效 |
| 2.6 | 私有部署与离线许可 | ToB | 专有 | 在无外网环境完成部署与激活；离线许可到期前可续，过期后按策略降级而非直接损坏数据 |
| 2.7 | 合规材料（安全白皮书 / 渗透测试 / DPA / SOC2 路线图） | ToB | 专有 | 四份材料齐备：白皮书可交付、渗透测试有第三方报告、DPA 可签、SOC2 有明确路线图与时间表 |

**Phase 2 完成判据**：一个真实受管环境（如某企业内网）完成 POC，且 2.1–2.7 的验收
证据齐备。

### 明确不做

| 不做 | 原因 |
|---|---|
| 云浏览器 | 与"数据不出本机"定位直接冲突，做了等于放弃唯一护城河 |
| 指纹伪装 | 合规与法律风险；README/商店文案零容忍此类字样 |

## 5. 审计事件 schema v0（Phase 0.6 的实现依据）

### 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | 全局唯一（UUID） |
| `ts` | number | 事件时间戳（epoch ms，UTC） |
| `actor` | string \| null | 谁发起的：agent 名或用户标识，可为空 |
| `session_id` | string | 会话标识 |
| `action` | string | 动作名（如 click / fill / evaluate / upload） |
| `target` | object | `{domain, url}`。**脱敏**：URL 的 query 参数默认丢弃或 hash；只保留域名与路径 |
| `params_hash` | string \| null | 参数不存原文，存 hash；另附白名单字段（如 method） |
| `result` | object | `{status: ok\|err, error_code}` |
| `duration_ms` | number | 动作耗时 |
| `policy_decision` | string | `allow` / `deny` / `confirm` |
| `prev_hash` | string | 前一条事件的 hash（链） |
| `hash` | string | 本事件内容的 hash（含 `prev_hash`） |

### 存储与保留

- **存储**：本地 append-only 文件（JSONL），一行一事件；后续可选 SQLite 索引。
- **轮转**：单文件 ≤10MB，保留最近 5 份；轮转**不破坏 hash 链**（新文件首条
  `prev_hash` = 旧文件末条 `hash`）。
- **保留策略**：默认保留 90 天，可配；崩溃/断电后已落盘事件仍可校验。

### 隐私红线（写入代码注释与文档）

- **原始参数与页面内容绝不进审计。** 只记"做了什么动作、对哪个站点、结果如何"。
- URL query 默认丢弃或 hash；不存 evaluate 代码、不存 fill 的值、不存页面内容。

### v0 验收标准

给定 3 个动作（如 click / fill / upload），审计文件里能查到 **3 条**记录，且：

1. 每条字段齐全（上表全部字段存在）；
2. hash 链可校验：从首条到末条逐条重算通过；
3. `target` 中**不含** query 原文，`params_hash` 非原文；
4. 篡改任一条记录内容后，链校验失败。

> 现状说明：daemon 已有最小 `audit()`（`{ts, action, who, detail}`，且 `detail` 只到
> method/url 层、不含 code/value），但无 `event_id` / `session_id` / `result` /
> `duration_ms` / `policy_decision` / hash 链，且默认只在 `--audit` 时落盘。
> v0 = 在现有钩子上补齐字段与 hash 链，并把落盘改为默认开启。

v0 实现位置：daemon/audit.py + tools/audit_test.py

## 6. 风险登记（诚实版）

| 风险 | 级别 | 说明与对策 |
|---|---|---|
| **ToB 的销售是"人"的活** | **最大** | 谁卖、卖国内还是海外、走什么渠道——**这是最大的非技术风险**，技术做完也解决不了。国内走集成商/渠道 vs 海外走 PLG+销售，是两条完全不同的组织能力。必须在 Phase 2 启动前先回答这三个问题，否则做完卖不掉 |
| 安装包签名/公证周期 | 高 | 外部依赖以周计，Phase 0 第一周启动申请 |
| 模板维护成本 | 中 | 只覆盖高频任务，不承诺全站；用编排兜底 |
| 合规材料周期 | 中 | 渗透测试/SOC2 以月计，Phase 2 首周启动 |
| 免费竞品持续压价 | 中 | 不在桥层竞争，靠管控/支持/合规差异化 |
| 一人团队带宽 | 高 | Phase 0→1→2 串行，不并行；每阶段有明确完成判据，不过不推进 |
